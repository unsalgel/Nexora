## Anahtarlar ve migration

OTP HMAC anahtarı, zorunlu JWT imzalama anahtarından (signing key) HMAC-SHA256 algoritması ve etiket domain separation kullanılarak türetilir. Gizli veya devreye giren başka bir fallback key yoktur. JWT key değiştiğinde bekleyen OTP'ler de geçersiz olur; kullanıcı yeni kod istemelidir. JWT secret tüm instance'larda aynı tutulmalıdır.

`20261010193605_HardenSessionsAndCommerce` migration kaynakta eski plaintext OTP/refresh kayıtlarını siler ve mevcut kullanıcılara ayrı rastgele security stamp atar. Bu geçiş tüm eski oturumları sonlandırır; eski JWT'lerde yeni claim'ler bulunmadığından ayrıca reddedilir. Yeni digest alanlarında eski plaintext satırların kalması desteklenen bir uyumluluk yolu değildir. Migration ve snapshot ana akış tarafından konsolide edilmiştir; gerçek PostgreSQL yürütme sonucu birleşik test raporunda belirtilir.

Auth e-postaları final `SaveChanges` öncesinde aynı scoped DbContext'e outbox olarak eklenir. Kullanıcı/kod ve teslim edilecek e-posta aynı commit'tedir. Outbox payload'ları DataProtection ile şifrelenir; deployment key klasörünü kalıcı ve erişimi sınırlı tutmalı, tüm worker/API instance'larına aynı key ring sağlanmalıdır. Key ring dosyalarının işletim sistemi/storage seviyesinde korunması operasyon sorumluluğudur.

Forwarded headers yalnız loopback ve açık `ReverseProxy:KnownProxies` IP listesine güvenerek okunur; tüm private ağları veya development içindeki her kaynağı güvenilir proxy sayan varsayılan kaldırılmıştır. Native env örneği `ReverseProxy__KnownProxies__0`dır. IP limiter gerçek client IP için doğru gateway konfigürasyonuna ihtiyaç duyar.

Profil sözleşmesi: `PUT /users/me` mevcut alanlar yanında e-posta değişirken `currentPassword` alır; yanıt `email` ve nullable `pendingEmail` içerir. `POST /auth/verify-email` pending adres ve kod alır; başarılı adres değişikliği sonrası yeniden giriş gerekir. `resend-verification-code` pending adresi destekler. `SessionRevoked {message}` ve `AccountFrozen {message}` UI oturumu kapatır.

## Test kanıtı ve sınırlar

İlk auth/user/chat regression turunda 51 test geçti. Yeni eklenen 11 unit regression, 3 PostgreSQL testi ve 1 Redis testi son birleşik doğrulama turuna dahildir. PostgreSQL testleri `NEXORA_TEST_POSTGRES` tanımlıysa fixture'ın oluşturduğu izole `nexora_review_test_<guid>` veritabanında migration çalıştırır; ortam değişkeni yoksa açıkça skip edilir. InMemory testler PostgreSQL transaction/isolation davranışını kanıtlamaz. Son birleşik koşu sonucu ana düzeltme raporuna kaydedilir.

JWT stateless imza denetiminin yanında bir DB sorgusu gerekir; bu bilinçli olarak anlık iptal doğruluğu sağlar. HTTP/hub authorization kontrolünden önce başlamış bir işlem, daha sonra gelen rol iptalinden otomatik olarak geri alınmaz. Private hub mesajları gönderimden hemen önce kontrol edilir; boşta socket'ler monitor periyodunda kapatılır. Registry mevcut API instance'ının bağlantılarını tutar; çok instance'a broadcast fanout/backplane bu kapsamda eklenmemiştir. Her instance DB'ye karşı kendi bağlantısını denetler.

HTTP IP rate limiter process-local'dır. Redis login hesap denetimi ve DB OTP caps instance'lar arasında ortaktır; process-local IP limitinin çok instance toplamını sınırlaması için reverse proxy/shared gateway limiti ayrıca yapılandırılmalıdır. Forgot/resend akışlarında account-enumeration için HTTP metni ve status eşitlenmiştir; ağ/DB/e-posta aşamalarının bütün timing yan kanalları ölçülüp eşitlenmiş değildir.

AI metni güvenilmeyen tavsiye içeriğidir; product-card verisi doğrulanır, doğal dildeki bütün model iddiaları garanti edilmez. Sistem prompt'unda özel veri/secret yoktur ve modelin sipariş/ödeme/hesap değiştiren araç erişimi bulunmaz. Cleanup batch kapasitesinin aşılması halinde retention backlog'u ve worker sağlığı izlenmelidir. Gerçek SMTP teslimi, DB/Redis outage, çok instance yük ve gerçek SignalR transport testleri için CI/entegrasyon sonuçlarına bakılmalıdır.
